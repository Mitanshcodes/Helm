# P3 status: learning and evaluation

## Done (initial gestures.py and adapt.py by P1; personalized classifier integrated by P3)
- `gestures.py`:
  - `GestureModel`: regularized logistic regression on selected facial deltas, with explicit "none"
    examples and distance rejection. Validation holds out complete takes/negative recordings and fits
    preprocessing inside each fold. Atomic `.npz` persistence stores raw enrollment and training
    settings; legacy profiles load and refit. `copy()` supports fitting off the pipeline thread.
  - `TakeRecorder`: per take "get ready" 1 s / "now, and hold" 1 s / "relax" 1 s (steps `take_1..take_N`);
    positives = top 60% of hold frames by distance from neutral; second half of each relax window goes to
    `recorder.rest` and the runtime adds it to "none". Negatives mode: 15 s "Talk, look around, laugh".
    Timer pauses while the face is lost.
  - `GestureEngine`: blendshape = `s.expr` of sources, `combine` min or max (default max). Learned
    gestures use a single winner with about 67 ms confirmation/release, yielding binary levels for
    the Mapper without a second debounce. Face loss, stale timestamps and model replacement reset
    qualification. Breath gestures are handled by the Mapper.
- `adapt.py`: `FatigueTracker`: attempt = level past 0.3 until it falls below 0.15; baseline = peaks in the
  gesture's first minute; recent = peaks after that in the last 2 min; with 3+ of each and recent median
  < 75% of baseline, scale = ratio (min 0.5); recovers when peaks come back. Notices name the gesture and %.
- Runtime (P1, `main.py`): fit + save run on a worker; the new model is used at once (old classifier until
  the fit lands). `gesture_trained` adds a `message` when accuracy < 85%.
- Tests cover synthetic separation, exclusion of pose/breath from learned features, rejection, temporal
  confirmation, face loss, mapping modes, persistence, recorder timing/selection and fatigue. Independent
  talking-session reliability is not established; the held-out `random.mov` still produces five false commands.

- Teaching paced like calibration (user's request): per take "get ready" 3 s (baseline face), "now, and hold"
  waits until the face is 0.25 away from that baseline (blinks and breath ignored) and records 1.5 s of the move
  held (nudges at 3 s, gives up at 8 s keeping the furthest frames), "relax" 2.5 s. Steps `take_N_ready/go/relax`
  and `read_aloud` (the names P4's teach flow and Wizard already style).

- Evaluation tooling (P1, at the user's request), all of SPEC 12 except running it on people:
  - `eval/latency.html`: square turns white while A is down on any pad (Gamepad API every frame), press count.
  - `eval/target_test.html`: ISO 9241-9 ring of 9, 2 distances x 2 widths, practice block, conditions
    (c) helm / (d) fixed / mouse, rate or position cursor, per-block throughput on screen, CSV download.
    Driven end to end in headless Chrome (mouse): page throughput equals `analysis.py` on the same CSV.
  - `eval/false_triggers.py`: replays `rec_<player>.npz` with recorded timing (`ReplaySource(realtime=False)`
    now keeps it) through (a) raw 0.5 threshold on the mapping's face gestures and (b) the real Normalizer,
    GestureEngine, FatigueTracker, Mapper with face-lost and pause rules; per minute (reading, chatting,
    video) and per gesture.
  - `eval/analysis.py`: latency (median, p90), false triggers, throughput, LOTO and launch-to-race extras;
    `latency.png`, `false_triggers.png`, `throughput.png` (blue Helm vs orange baseline, palette validated),
    `headline.json`, and the `ui/src/results.ts` block. Missing data prints "not measured".
  - `eval/PROTOCOL.md`: step-by-step for all three plus the CSV formats. `matplotlib` appended to requirements.

## Decisions
- The classifier selects facial channels per gesture, scales with a 0.05 standard-deviation floor,
  and excludes neutral, head pose and breath. This avoids amplifying unrelated low-variance channels.
  See `eval/LEARNED_GESTURES.md` for the study settings and limits.
- `FatigueTracker` uses a fixed attempt level (`FATIGUE_ATTEMPT_LEVEL`) since it does not see thresholds.
- Fit/predict timing must be measured on the demo laptop for the integrated classifier.
