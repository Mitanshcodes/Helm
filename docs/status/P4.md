## Decisions
- The dashboard is now light, not the "dark background" of spec section 9. The user (P4) chose this;
  tell the captain so section 9 can be updated.
- The redesign brief used a different draft protocol (`type` commands, `axes.lx`, `pose`, `range`,
  `sipnpuff`). The UI stays on the real protocol of spec section 8. Not shown because the state does
  not carry it: the player's yaw range caption. Button badges, modes and the sip-and-puff chip labels
  need `state.mapping` (see requests); until then badges show a dash.
- The server mirrors the preview and landmarks, so the UI does not mirror again.
- "Software delay" tile is `latency_ms.total` (capture to pad write), deliberately not called
  motion-to-input: that number comes from P3's slow-motion eval.
- UI packages: React 18, Vite 5, TypeScript 5. `ui/package-lock.json` is committed.
- Events go through one hub so the default window and the overlay window both receive them
  (`pop_events()` drains, so per-socket polling would lose events for one of them).
- Command replies are appended to a per-socket list and flushed by the broadcast loop, so only one
  task ever writes to a socket.
- The protocol has no success reply for `set_mapping`: the UI treats 600 ms without an `error` event
  as "Applied".
- Only the default window auto-starts calibration; the overlay never does (two windows would both send).
- Names are validated in the server: gesture `[A-Za-z0-9_]{1,32}` and not `none`; player and game
  `[A-Za-z0-9_-]{1,32}` (they become paths under `profiles/`).
- `httpx` appended to `requirements.txt` for FastAPI's TestClient (the socket test skips without it).
- Local dev machine has Python 3.14 only (no 3.11); a `.venv` on 3.14 runs all tests and the smoke run.
